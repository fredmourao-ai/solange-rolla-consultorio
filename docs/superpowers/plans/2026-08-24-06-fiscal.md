# Fiscal and NFS-e Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar o núcleo fiscal desacoplado e seguro para emissão/consulta/cancelamento de NFS-e, sem colocar credenciais ou regras municipais dentro de agenda/financeiro.

**Architecture:** `fiscal` consome snapshots mínimos de Pessoa/Receivable/Service por contratos públicos. `NfseProvider` é adapter; dev/staging usam mock ou ambiente oficial restrito. Produção live só é habilitada após confirmação do emissor fiscal, cadastro municipal/código de serviço e credenciais.

**Tech Stack:** PostgreSQL, TypeScript, Supabase Queue `fiscal`, Edge Function/worker, private Storage, API NFS-e Nacional adapter, Vitest, pgTAP.

**Spec:** `docs/superpowers/specs/2026-08-24-multiagent-architecture-design.md`

## Global Constraints
- Não assumir se o emissor definitivo é PJ ou profissional pessoa física até validação fiscal formal.
- Nenhuma NFS-e real é emitida em testes/staging.
- `NFSE_LIVE_ENABLED=false` por padrão.
- Fiscal status é independente de payment/appointment status.
- Documento fiscal original e eventos de cancelamento/substituição são preservados.
- XML/PDF ficam em bucket privado; logs nunca contêm credenciais ou documento integral.

- [ ] **Step 1: Implementar provider contract test**

Mesma suite roda contra mock e adapter sandbox/restricted: issue request, query status, parse errors e cancel request quando suportado.

- [ ] **Step 2: Timeout/retry classification**

Timeout/5xx/429 => retryable; erro de cadastro/tributação => final até correção humana. Nunca repetir emissão automaticamente se resposta é ambígua sem consultar status/protocolo primeiro.

- [ ] **Step 3: Feature flag live**

Adapter live aborta antes da rede se `NFSE_LIVE_ENABLED !== true`. Staging aponta somente para ambiente oficial de homologação/restrito quando disponível.

- [ ] **Step 4: Worker**

Persistir attempt antes/depois da chamada; após crash, consultar por idempotency/external correlation antes de emitir novamente.
