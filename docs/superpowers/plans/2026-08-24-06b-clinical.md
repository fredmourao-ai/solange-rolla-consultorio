# Clinical Records Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar registro psicológico segregado, criptografado e auditado, acessível somente à psicóloga autenticada em AAL2.

**Architecture:** Tabelas clínicas vivem no schema `clinical`, que não é exposto diretamente pelo API schema. A aplicação acessa envelopes cifrados por RPCs controladas e RLS; decriptação ocorre somente no servidor após autorização. Leituras também geram audit trail.

**Tech Stack:** PostgreSQL schemas/RLS/RPC, SensitiveDataCrypto AES-256-GCM, Supabase Auth AAL2, private Storage, Next.js server components/actions, pgTAP, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-24-multiagent-architecture-design.md`

## Global Constraints
- Secretary/accounting nunca recebem plaintext, ciphertext, metadata clínica ou anexos.
- Owner precisa `psychologist_owner` + perfil ativo + AAL2.
- Texto clínico nunca é persistido em claro.
- Registro clínico não aparece em busca global/financeiro/relatórios administrativos.
- Correções preservam versão anterior; não existe edição destrutiva silenciosa.
- Logs técnicos nunca recebem plaintext clínico.
